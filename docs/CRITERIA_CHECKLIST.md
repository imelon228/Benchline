# Course grading checklist

| # | Criterion | Evidence and boundaries |
| --- | --- | --- |
| 1 | Code structure and design | [Architecture](ARCHITECTURE.md), `Benchline.slnx`, `ScheduleRules`, `RecoveryPlanner` and `Workshop` show inward dependencies and pure transitions. |
| 2 | Component reusability | `src/Benchline.Components` has typed parameters, `NoticeBar.OnDismiss`, `ThemeToggle.Settings`, `ScheduleGrid`, `ScheduleCell` and `ItemStack<TItem>`. `/components` shows the library. `ComponentTests` and `WorkshopViewTests` exercise shared components, views and typed callbacks. |
| 3 | Cross-platform compatibility | `manifest.webmanifest`, the published service worker and the [QA matrix](QA_REPORT.md) cover the PWA, browser engines and device viewports. See the matrix for host coverage. |
| 4 | State management | `BoardStore` has actions, reducer, selectors and pending slot rollback. `Home` refreshes on SignalR revisions and passes a cascaded theme. `workshop.js` retains the theme preference. |
| 5 | Interface design | `styles.css` defines the monochrome light and dark themes, IBM Plex type and ruled layouts. Pattern and text distinguish station and session states. [Mockups](presentation/mockups/workflows.html) show the main interactions. |
| 6 | User experience | `Home.razor`, `WorkshopNotices`, `BookingDialog`, `RecoveryDialog` and `AuditLog` cover loading, empty and offline states, disabled reasons, validation, dismissible notices and native dialogs. `timetable.spec.js` verifies slot selection and focus. The accessibility checks cover sign-in, the board, both dialogs, audit and the component library in both themes. The timetable and dialogs use Astana time (UTC+5). See [QA](QA_REPORT.md) for remaining manual checks. |
| 7 | Responsiveness | `styles.css` uses a wide timetable and a wrapped station layout on phones. `layout.spec.js` checks filtering and page overflow at 360, 820 and 1440 pixels. |
| 8 | Core functionality | `WorkshopApiTests` and `flows.spec.js` exercise booking, cancellation, outage, recovery, live refresh and audit. `ScheduleRules`, `SchedulingTests`, `RuleBoundaryTests` and `UnsupportedCommandTests` cover restoration, deadlines and typed faults. |
| 9 | Advanced functionality | `WorkshopHub` broadcasts revisions. `WorkshopEndpoints` enforces role policies and exposes paginated audit history and CSV export. |
| 10 | Resilience | `Program.cs` configures ProblemDetails. The client uses Polly-backed read retries and circuit breaking. `EfScheduleRepository` writes atomically. Tests cover the offline shell and Demo startup against an expired volume, including in-place display name and campus space updates. |
| 11 | Efficiency | Release publishing trims the WebAssembly payload. The client uses invariant globalization, an image-free static shell, self-hosted Latin font subsets, immutable fingerprinted assets and negotiated compression. The component showcase loads on demand. Audit pages use a cursor and render visible rows with Blazor virtualization. Cold-load measurements are in [QA](QA_REPORT.md). |
| 12 | Scalability | `WorkshopDb` defines indexes. `Workshop.Audit` limits cursor pages. [Developer notes](DEVELOPER_NOTES.md) describe shared keys, PostgreSQL and a SignalR backplane for added replicas. |
| 13 | Resource utilization | `EfScheduleRepository.Read` uses a fixed number of no-tracking queries. `Home.razor` and `ItemStack` use stable keys. The hub invalidates by revision and the client serializes board refreshes. |
| 14 | Coverage | `Benchline.Unit.Tests`, `Benchline.Integration.Tests`, `Benchline.Components.Tests` and `tests/browser` cover different boundaries. [QA](QA_REPORT.md) reports the passing .NET and browser checks and coverage by project. |
| 15 | Quality assurance | [QA](QA_REPORT.md) documents the browser matrix, observed issues, performance and remaining device checks. |
| 16 | Documentation | [README](../README.md), [user guide](USER_GUIDE.md), [API examples](API.md), [developer notes](DEVELOPER_NOTES.md), [architecture](ARCHITECTURE.md) and [decisions](DECISIONS.md). The live API schema is at `/openapi/v1.json`. |
| 17 | Innovation | `RecoveryPlanner.Build` uses augmenting paths to recover the maximum number of compatible reservations. `RecoveryReassignsAFlexibleBookingToMakeRoomForATightDeadline` checks a case where first fit leaves a member without a slot. |
| 18 | Creative .NET use | Minimal API endpoint filters, request rate limiting, templated Razor, native dialogs through targeted JS interop, and immutable record families. |
| 19 | Professionalism | `Program.cs` configures HTTPS outside Demo, same-origin secure cookies, antiforgery, CSP, rate limiting and Serilog. `Dockerfile` runs as a non-root user. CI checks build and tests. Production account and equipment provisioning require deployment integration. |
| 20 | Presentation | [16-slide PDF presentation](presentation/Benchline_Presentation.pdf), [15-slide outline](presentation/presentation.md) and [linked interface mockups](presentation/mockups/workflows.html). |
